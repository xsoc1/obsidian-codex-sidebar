## Stable boundaries

- Preserve unrelated changes and original session/message IDs, questions, saved prompts, immutable sources, branches, concrete model/effort/Fast choices, note mappings, device scopes and edit records. Unknown legacy metadata stays unknown. Use validated migrations and merges, not a wholesale older-state restore.
- Use official app-server protocol, owned hidden processes, existing local login and ephemeral threads. Never read private credentials, attach to a private desktop socket or change global Codex config. Desktop/remote stores remain separate. A paired key intentionally selects the same independent remote agent; isolation is process/history separation, not a separate OS account.
- Explicitly load the enabled `math-writing` skill on every chat/completion turn; missing skills stop the request. This remains a private external dependency; [development instructions](docs/development.md) explain its acquisition and reproducibility boundary. Keep private skills, coursework, learning records, chats, tokens, machine paths and raw receipts out of Git/packages.
- Keep tools fixed to the current vault, read-only, bounded and version-checked. `obsidian_cli_read` permits only its command/parameter allowlist: no shell, eval, writes or cross-vault paths. Remote approvalPolicy stays `never`. Captured documents and tool results are reference material, not new user authority.
- Ordinary turn input is text plus discovered math-writing, with at most two supported PDF images. No arbitrary client skill paths. Gate new features on actual capabilities; connection checks never upgrade or restart a bridge.
- Separate actual selection, explanatory background and allowed write target. Replay/resend preserves original task/context; recapture is explicit. Source indexes record actual successful reads; Windows-copy content cannot replace a client's snapshot.
- Freeze answer Markdown base paths to the producing turn/quote chain. Later focus or file moves must not retarget old relative links. Observed CurrentPath is for source navigation; unknown targets need an explicit fallback, never a same-name guess.
- Client Obsidian API writes require preview, user confirmation, host-generated targets/versions, stale checks, journal/idempotency, readback and safe undo. Respect frontmatter readonly. PDF/teacher/source excerpts stay read-only. Never execute model-defined JS/shell/arbitrary file operations. iPad writes occur on iPad.
- Distinguish problem statements, complete answers and outlines. Attribute necessary added problem conditions. Complete answers get minimal corrections preserving the user's route/structure/notation/wording; replacing a failed route requires the user's decision. Expand outlines along the original route. Lecture rewriting does not authorize changing teacher problems or other answers.
- Keep full explanations and default integrated follow-ups; obey explicit local-answer requests. No fixed blank ratios or forced Socratic questions. Schema validity is not mathematics certification.
- Keep edit-cache lifetime semantics: subsequent successful rounds in the original session, default 1 or configurable N/never. Preview-generation round does not count; adopt/undo re-arms. Failed/interrupted/completion/duplicate/other-session events do not count. Do not retroactively expire untracked legacy records or delete chats/sources/notes.
- Completion proposes text; confirmation stays in the sidebar. Preserve native Tab, Enter/Shift+Enter and Chinese IME. Source/cursor changes invalidate suggestions; IME cancels in-flight requests. Sidebar controls use visible labels/aria-labelledby without hover explanations. Leave rendered-note attributes/global tooltips alone.
- New logic belongs in testable modules. Frontend must not statically import Node/Electron. Keep the existing framework and stable writer; avoid unrelated rewrites.
