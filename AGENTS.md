# Codex Sidebar development

## Objective and scope

- User requested a Windows desktop Obsidian plugin using real local Codex login and sessions, with the open/close control on Obsidian's left ribbon.
- Version 0.6.0 adds a mobile-safe remote client and an independently started Windows bridge; answer follow-ups, explicit saved choices, math-writing and the user's editing policy remain.
- User's mathematical editing policy: distinguish problem statements, complete answers and solution outlines. Problem conditions may be supplemented with clear attribution and justification. Complete answers receive the smallest necessary logical corrections, preserving route, structure, notation and wording. A fundamental failure requiring replacement must be explained and put to the user for a decision before rewriting. Expand solution outlines strictly along their original route. Match the supplied draft/user samples, not skill specimens or other authors. These boundaries override generic skill writing advice.
- Source lives here. Installed files belong to the vault's ignored `.obsidian/plugins/codex-sidebar` directory. Do not put generated files or private session data into the notes repository.
- Preserve unrelated vault changes. Do not modify notes or assignment answers when testing selection capture.
- Use the official Codex app-server JSONL protocol over an owned hidden child process. Never parse private credential files or attach to a private desktop socket. Reuse the current Windows user's Codex login.
- Questions use a read-only sandbox. Approval requests must be shown to the user; unsupported server requests must return an explicit error. The plugin-hosted `obsidian_cli_read` tool has a fixed vault and command/parameter allowlist, no shell, eval, writes or cross-vault paths. Do not broaden it into an arbitrary command bridge.
- Completions propose text without modifying the source. Confirmation is a button in the sidebar; preserve native Tab. Reject stale documents/cursors/paths and cancel pending requests during IME. Tests may use an explicitly named temporary scratch note and must remove it afterward, preserving existing notes.
- Sidebar fields have no hover explanations. Preserve accessible names via native labels or hidden text referenced by aria-labelledby; aria-label triggers Obsidian's hover tooltip and must not be used on the sidebar's own fields/containers. Do not disable tooltips globally or strip attributes from rendered note content.
- Model/effort selections are concrete saved choices, loaded with plugin state and saved on changes/sidebar close. Do not read native global model defaults or add a separate default-model configuration. Unavailable saved selections stay visible and require reselection rather than silently changing an existing choice.
- Answer follow-ups capture rendered selection plus the assistant's Markdown snapshot. Only assistant message bodies qualify. Pin/cancel in the composer; selection alone never sends. Preserve quoted snapshots during replay and edit/resend. Do not claim exact Markdown character mapping. Test using temporary plugin sessions without editing source notes.
- iPad remote initial implementation is complete, with real-device acceptance still pending. User accepts keeping Windows online and explicitly requires an independently opened/isolated remote agent. Each paired key owns a separate hidden app-server, transcript file and ephemeral threads; the same key intentionally selects the same agent. This is runtime/process/history separation, not a separate account or OS-user security boundary. Desktop data.json stays separate; remote URL/token are device-local localStorage, not an OS keychain. Read [setup and boundaries](docs/ipad-setup.md) and the historical [feasibility research](docs/ipad-support-research.md) before mobile/backend changes. A mobile-safe load test or Windows HTTPS test does not establish iPad device acceptance.
- Use tabs, standalone braces, snake_case for own multiword functions, PascalCase for own variables. Obsidian overrides retain API names.

## Commands

- `npm ci`
- `npm run build`
- `npm test`
- Build generates `bridge.cjs`; `scripts/start-bridge.ps1` and `scripts/stop-bridge.ps1` manage only the verified independent bridge and descendants. Default private config is outside the vault under LOCALAPPDATA/CodexObsidianRemote. No startup task is registered.
- Install `manifest.json`, `main.js`, `main.js.map`, `styles.css` into the plugin directory, preserving `data.json`.
- Native CLI: `obsidian vault=<vault> plugin:reload id=codex-sidebar`; then `dev:errors` and native DOM/screenshot checks. Local executable paths and installation details are recorded in ignored `LOCAL_DEV.md` when present.
