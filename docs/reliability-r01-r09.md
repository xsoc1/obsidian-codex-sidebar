2026-11-09。用户要求完成 R01—R09 并安装、发布。起点 `191a776f8a61209e7b84868e639c00dfb84ecce9`，起始工作树干净，已 fetch；设计参考不代替当前源码。Node 24.17.0 下 `npm ci`、构建及原 426 项测试通过。本轮完整构建和测试：526 通过、0 失败、1 项性能基准跳过；该基准已另外显式运行。T01—T12/beta.13 的验证属于历史。

## 使用变化

- 回答已收到但磁盘保存失败时，正文和公式仍可阅读、复制，显示“尚未保存”。4 次有界自动退避后可点“重试保存”；只重试存储，不再请求模型。保存并读回前不计成功回合，不授予修改稿采用资格；暂停当前会话的新提交，其他会话不受影响。
- 切换模型同时更新协议、图片依据和思考选项。目录明确不支持图片时禁止发送图片；未知时按实际模型确认，不继承另一个模型的确认。旧同模型图片开关保留可用，但不冒充已核验能力。
- PDF 文字选区补图后，来源分别显示“原文字选区”和“补充图像”；前者精确返回原文字，后者返回对应页/框。最多两张图的限制不变。
- 历史材料清单区分“本轮已提供正文”“只提供补读定位”“实际补读成功”和未知。优先展示问题/标题，完整 ID、版本和预算放在详情。只有宿主实际成功读到的分页才算补读成功。
- 从整合说明跳回原段落后，可点“返回刚才阅读处”。按消息及可靠 Markdown 块恢复局部位置，支持连续往返；用户主动滚动、切换会话或后端会使迟到导航失效。

## 协议、升级与恢复

规范 schema 2/同步协议 2 不变。Selection、EvidenceDigests、InputLedger.Identity/MaterialLabels/ReadRecords 为可选元数据。旧输入、快照、引用、分支、完成状态及设备身份保留，旧未知不补造。桥的成功补读记录走既有 message checkpoint，不新增 RPC/技能输入项。远程实际补读展示需先升级桥，再更新同配对客户端。

备份规范状态、收据/日志/blob、设备草稿、修改数据库和 PDF 图库，只替换程序。旧程序可能丢弃新增 metadata，回退前先在新版完整导出并于副本核对，不能用旧完整备份覆盖后来历史。未读回的保存屏障只在进程内保留；导出遇到缺失证据停止并保留定位，不宣称备份完整。

## 发布检查发现的等待竞态

beta.14 的本机 526 项通过，但远端 Windows/Ubuntu 及 release CI 的旧端到端用例在模型 idle 后立即请求预览，早于新结果保存屏障完成。产品正确拒绝了提交。用例改为同样有界等待 Busy 或 BackendSaveBlocked，保留所有预览、零提前写入、确认和安全撤销断言，不扩大超时。beta.14 标签保留、不移动且不发布；最终采用 beta.15，实际 CI 收据另记。
