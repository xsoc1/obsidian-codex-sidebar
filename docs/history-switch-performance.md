# 笔记切换与历史显示速度

2026-10-26, 用户报告 Windows 数学库切换笔记再返回时历史看似消失, 随后明确确认是加载速度问题并要求加快.

## 原因和实现

只读检查确认已有会话和消息仍在内存与磁盘. 原实现离开会话时销毁全部渲染节点, 回来后逐条重新执行 Markdown 与数学排版, 全部完成才显示. 原生检查时该笔记有 105 条消息, 用户可能在等待期间看到上一会话的空白欢迎页.

1.0.2 候选在 MessageList 内保存最近离开的两份会话视图, 总计最多 300 张消息卡片, 当前显示的会话不计入此预算. 回来时依据消息 ID 与内容/状态键复用原节点, 有变化的卡片单独更新. 使用最久未访问的次序淘汰, 淘汰和关闭时释放组件, 不改变或删除持久化聊天记录.

缓存保留跟随末尾状态、阅读锚点和滚动位置. 消息键包含当前 Markdown 来源路径, 避免笔记变化后复用错误的相对链接渲染. 缓存作用域区分桌面与远程设备身份, 即使会话 ID 相同也不混用. 中断的异步排版释放新节点, 不破坏原缓存; 修改提案状态和已变更消息继续失效更新.

缓存只在当前侧栏生命周期内有效. 首次打开、重启插件、超出预算而被淘汰的会话仍需正常排版. 该变更不扩大模型上下文、不压缩会话文本、不请求模型、不更改设备存储格式或远程桥.

## 实际验证

基线构建和 130 项测试通过. 新回归在旧实现上失败: 返回会话时原节点已销毁、历史重新渲染且阅读位置丢失. 候选构建和 135 项测试通过, 覆盖返回复用、变更/删除消息、最久未访问淘汰、300 张卡片预算、取消的缓存刷新及原有流式/滚动/关闭清理.

`CODEX_LAYOUT_BROWSER=<Chromium 路径> CODEX_LAYOUT_APP_CSS=<Obsidian app.css 路径> node scripts/check-history-switch.mjs` 对照不可变 1.0.1 的 main.ts/MessageList 与当前候选. 实际 CodexView 配异步 SDK fixture, 原创 35 张卡片, 明暗及桌面/移动四组合: 旧版返回重新渲染 35 次, 约 651—660ms; 候选零次重新渲染, 约 2.8—3.1ms. 原卡片身份、阅读位置、来源路径失效和设备作用域检查均通过. 这是 fixture, 不是原生 MathJax 或 iPad 性能.

另使用两个独立临时 SDK 插件运行同一原创公式样本, 基线只替换为 1.0.1 MessageList. 原生 Markdown/MathJax 共 51 个公式容器, 零公式错误; 返回时旧版重排两张卡片约 252ms, 候选零次重排约 10ms, 原公式节点与阅读位置保留. 现有五次流式增量检查仍通过. 此为当前机器的一次原生组件样本, 不是日常 105 条完整会话的耗时或普遍速度保证.

临时插件均卸载且两份独立目录精确清理, 无残留实例、manifest 或启用项. 比较前后日常会话、修改记录和笔记关联数据一致, 未请求模型或写入笔记. 检查脚本曾把未序列化的 undefined 可选字段当成数据差异, 已改为比较完整 JSON 可保存值, 未回滚用户状态或将其误报为产品缺陷.

原有 24 个流式、4 个上下文、4 个完整视图 SDK 浏览器检查通过. 磨砂、折叠、两个提交动作、回答引用和原生 Tab/IME 逻辑保持. 未做 iPad 真机或日常插件覆盖安装; 安装和发布需按用户的明确部署授权执行.
