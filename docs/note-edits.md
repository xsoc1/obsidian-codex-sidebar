# 普通聊天修改 Markdown (0.9.0)

## 使用

1. 打开个人 Markdown 笔记, 在编辑视图/实时预览选中要修改的文字, 或在阅读视图捕获源块. 上下文卡片可检查路径和原始 Markdown.
2. 在原来的聊天输入框写“请修正这段证明, 最小改动”. 自动识别修改请求时, 按钮变为“生成修改预览”, 可见提示标出目标和范围. 普通解释/检查快捷按钮继续只作问答. “修改选项”可明确选择“仅问答”或“明确生成修改预览”. 自动识别是保守的关键词判断, 不是授权判断或自然语言理解保证.
3. 回答出现“笔记修改提案”, 显示目标、原文类型、捕获时间、字符范围、理由和差异. 展开查看修改后的片段, 审核公式及逻辑. 生成完成不等于笔记已改.
4. 点击“确认写入此文件”. 当前客户端重新检查基线和当前内容, 写入并回读, 状态变为 applied. 取消提案不修改笔记. 已采用后, 当前全文仍等于修改后内容时可“安全撤销本次修改”; 有后续编辑时拒绝自动撤销.

默认只替换精确源选区; 阅读选区按已映射的完整 Markdown 源块替换, 不声称精确对应渲染字符. 没有精确选区时, 捕获的源文本/源块是替换范围. 整篇修改必须手动选择“当前整篇笔记”, 仍绑定原上下文的文件和版本, 不因焦点变化换目标. 缺少快照时发送前捕获当前 Markdown. 截断片段、只有渲染文字或版本过期时请明确重新捕获. 默认范围最多 24000 字符, 文件基线最多 500000 字符, 输出最多 48000 字符.

“原文类型”可指定完整答案、思路、个人题面或讲义. 完整答案保留路线/结构/编号/符号/措辞, 只修必要错误; 思路沿原路线展开, 风格沿原稿. 未批准的根本重建返回 needs-decision, 无可采用稿; 你先决定方案, 再明确发起修改, 仍需审核提案. 提问解释时不强制反问或自动改稿. 教师原题、源书摘录和 PDF 不生成写回, 也不把讲义新写授权扩展到它们.

只读标记可用 frontmatter `codex-readonly: true`, 或 `study-role`/`role`/`note_type` 为 `source-excerpt`/`teacher-problem` (也识别“源书摘录”/“教师原题”). 也尊重已加载课程清单中重叠的只读单元. 这些标记不能自动辨认未标注材料的版权/来源角色; 应在修改选项中如实选择角色. 不修改只读工具 allowlist, 不让模型调用 CLI/shell 写入.

## 协议与存储

复用原 app-server、math-writing、历史和 Markdown 渲染. 普通修改 turn/start 仍只有 text + math-writing skill 两项; 任务序列化在 text 内, 不添加未知 RPC 字段、第三个技能、执行代码或文件工具. Windows 和独立远程桥的 sandbox=read-only、approvalPolicy=never 不变. iPad 的写入在 iPad 完成, Windows 不操作同步副本. 已有 0.8.0 桥可继续使用, 不需要改配对密钥或重启桥.

宿主 TaskSpec: Action=edit, Scope=note-edit, SchemaVersion=1; 保存原始 Source、精确 WriteUnit、输入 Role 及实际目标/基线/字符范围. ContextSnapshot.Selection 是可选精确源字符区间; 旧快照缺失它时只在源行/源块内容完全匹配时降级. Target.Before 全文仅留在设备本地修改日志, 模型/远程聊天只收到捕获的 Source、WriteUnit 与清空 Before 的目标. 替换范围和版本从实际客户端产生, 不信任模型提供目标.

模型最终输出严格校验为:

```json
{"schemaVersion":1,"kind":"note-edit","status":"proposal","markdown":"范围的完整替换文本","rationale":"最小改动及理由"}
```

status 仅可 proposal/needs-decision/no-change. 后两种的 markdown 必须 null; proposal 可为空字符串表示删除绑定范围. 拒绝未知字段、路径、操作、脚本式插件块、HTML、自动嵌入、损坏 JSON、常见双重转义和中断输出. 普通代码围栏可作为笔记文字写入, 预览中以原文显示; 不执行它. 格式有效不认证数学正确或写入权限.

写回重用 ConfirmedWriter/ObsidianWriteHost: 预览 → 明确确认 → 校验目标/哈希/唯一块 → 检查当前编辑器和文件 → 先保存 pending 日志 → Editor.transaction 或 Vault.process 比较写入 → 回读 → applied. 替换范围外必须逐字保留. 编辑器支持未保存文本及原生撤销, 多编辑器不一致/多入口时拒绝. 重复点击、重启后的 pending 恢复、陈旧预览、迟到输出均有拒绝或去重路径. 提案不提供新建/删除文件、批量操作、路径迁移或任意执行; 讲义新稿继续走原工作台.

独立设备本地存储 `codex-sidebar-edits:v1:<vault-name>` 使用 schemaVersion=1, 不混进远程聊天或学习记录. 最多 50 个任务/提案、约 200 万字符 JSON; 达上限明确报错, 不自动丢弃旧记录. 插件设置可导出完整 JSON 和二次确认清除; 导出含原文基线. 清除不改笔记, 但旧提案不能再采用或撤销. 正在写入/撤销时禁止清除, 清除期间迟到模型结果不得恢复任务. 未知 schema/损坏数据原样保留, 不静默迁移或覆盖. 当前没有导入记录功能.

“编辑并重发”和“重新发送”复制原任务/来源/私有本设备基线到新分支. 原任务保留, 不换成当前焦点或重新捕获. 别的设备只有远程聊天、缺少原私有基线时明确拒绝重发写回和采用; 明确重新捕获后才能新建修改任务.

## 迁移与回退

当前为本地待发布构建, 日常 0.6.2 安装尚未覆盖. 安装前保留原四个构建文件和 data.json, 不覆盖聊天、具体模型/档次/Fast 选择、配对配置或学习记录. 旧版完全匹配的默认提示词升级为客户端确认写回说明, 自定义文本保留; 每轮仍附固定数学规则与修改能力边界.

仅升级插件四文件即可使用普通 Markdown 改稿, 兼容现有 0.8.0 桥. 重新打开侧栏, 明确重新捕获旧选区 (旧版消息可能没有版本). 不将旧文本建议自动升级为可写入提案.

回退只恢复插件构建文件, 保留 data.json 和设备存储. 回退不会自动恢复已采用的笔记; 请先安全撤销或使用 Obsidian 文件历史/自己的备份. 旧版不能呈现新提案确认控件, 不因此清除本地记录. 本版 iPad 真机改稿尚未验收.
