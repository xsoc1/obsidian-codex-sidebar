# 普通聊天修改 Markdown (0.10.0)

## 使用

1. 打开个人 Markdown 笔记, 在编辑视图/实时预览选中要修改的文字, 或在阅读视图捕获源块. 上下文卡片可检查路径和原始 Markdown.
2. 在原来的聊天输入框写“请修正这段证明, 最小改动”. 自动识别修改请求时, 按钮变为“生成修改预览”, 可见提示标出目标和范围. 普通解释/检查快捷按钮继续只作问答. “修改选项”可明确选择“仅问答”或“明确生成修改预览”. 自动识别是保守的关键词判断, 不是授权判断或自然语言理解保证.
3. 回答出现“笔记修改提案”, 显示目标、原文类型、捕获时间、字符范围、理由和差异. 展开查看修改后的片段, 审核公式及逻辑. 生成完成不等于笔记已改.
4. 点击“确认写入此文件”. 当前客户端重新检查基线和当前内容, 写入并回读, 状态变为 applied. 取消提案不修改笔记. 已采用后, 当前全文仍等于修改后内容时可“安全撤销本次修改”; 有后续编辑时拒绝自动撤销.

0.10.0 默认“AI 自选当前笔记中的修改范围”. 初始选区是定位起点; AI 可选另一段或扩展到必要相邻内容. 短笔记提供全文, 长笔记提供起点附近最多 24000 字符的窗口, 不是整个 vault. 模型返回逐字复制的唯一原文, 客户端在本轮窗口内唯一匹配, 绑定实际偏移并展示“AI 选择的实际范围”和差异; 未找到/重复/越过窗口/只读范围时拒绝. 需要插入时把唯一一段原文作为锚点, 修改稿同时保留锚点与新增内容. 首版为单文件、一段连续原文的替换, 不支持任意跨文件或多个分散范围.

“严格只改选区 / 捕获的 Markdown 块”保留 0.9.0 行为: 编辑精确选区逐字符定位; 阅读选区用完整映射源块, 不声称精确对应渲染字符. 整篇修改仍须选择“当前整篇笔记”. 所有方式绑定原上下文的文件和版本, 不因焦点变化换目标; 旧任务重发保持旧方式, 不自动变成 AI 自选. 缺少快照时发送前捕获当前 Markdown; 原捕获已截断、只有渲染文字或版本过期时, 请明确重新捕获. 文件基线最多 500000 字符, 候选原文/固定范围最多 24000 字符, 修改稿最多 48000 字符. 长笔记窗口截断与原始选区截断分别登记, 不假装已经读取窗口以外内容.

选中文字后, 独立“笔记选中内容”卡片默认展开, 显示原文、路径、映射、捕获时间、截断和是否附带. 阅读渲染选区另可展开映射原文, 保留 LaTeX. 卡片用文本呈现, 不执行笔记代码/HTML. 它不藏在“上下文与学习”折叠区; 转到聊天框输入、复制回答或折叠控件不会换掉选区. 清除会取消待捕获结果. Windows 的四个区均可折叠, 首次只有发送区展开; iPad 首次全收起. 开合状态按本设备和 vault 名单独保存, 保留输入节点/草稿/模型选择, 不进入远程聊天状态.

“原文类型”可指定完整答案、思路、个人题面或讲义. 完整答案保留路线/结构/编号/符号/措辞, 只修必要错误; 思路沿原路线展开, 风格沿原稿. 未批准的根本重建返回 needs-decision, 无可采用稿; 你先决定方案, 再明确发起修改, 仍需审核提案. 提问解释时不强制反问或自动改稿. 教师原题、源书摘录和 PDF 不生成写回, 也不把讲义新写授权扩展到它们.

只读标记可用 frontmatter `codex-readonly: true`, 或 `study-role`/`role`/`note_type` 为 `source-excerpt`/`teacher-problem` (也识别“源书摘录”/“教师原题”). 也尊重已加载课程清单中重叠的只读单元. 这些标记不能自动辨认未标注材料的版权/来源角色; 应在修改选项中如实选择角色. 不修改只读工具 allowlist, 不让模型调用 CLI/shell 写入.

## 协议与存储

复用原 app-server、math-writing、历史和 Markdown 渲染. 普通修改 turn/start 仍只有 text + math-writing skill 两项; 任务序列化在 text 内, 不添加未知 RPC 字段、第三个技能、执行代码或文件工具. Windows 和独立远程桥的 sandbox=read-only、approvalPolicy=never 不变. iPad 的写入在 iPad 完成, Windows 不操作同步副本. 已有 0.8.0 桥可继续使用, 不需要改配对密钥或重启桥.

宿主 TaskSpec: Action=edit, Scope=note-edit, SchemaVersion=1; 自选任务另有 EditMode=ai. 保存原始 Source、候选/固定 WriteUnit、输入 Role 及实际目标/基线/字符范围. ContextSnapshot.Selection 是可选精确源字符区间; 旧快照缺失它时只在源行/源块内容完全匹配时降级. Target.Before 全文基线仅留在设备本地修改日志; 模型/远程聊天收到 Source、WriteUnit 与清空 Before 的目标. 自选短笔记的 WriteUnit 可能就是全文, 界面明确提示候选范围最多 24000 字符. 不能把“基线字段留在本地”误解为“自选模式绝不发送任何选区以外文字”. 实际偏移由客户端匹配决定, 不接受模型自报路径/偏移/hash.

模型最终输出严格校验为:

```json
{"schemaVersion":1,"kind":"note-edit","status":"proposal","markdown":"范围的完整替换文本","rationale":"最小改动及理由"}
```

status 仅可 proposal/needs-decision/no-change. 后两种的 markdown 必须 null; proposal 可为空字符串表示删除绑定范围. 拒绝未知字段、路径、操作、脚本式插件块、HTML、自动嵌入、损坏 JSON、常见双重转义和中断输出. 普通代码围栏可作为笔记文字写入, 预览中以原文显示; 不执行它. 格式有效不认证数学正确或写入权限.

自选模式额外且必须提供 `original`, proposal 时是窗口内唯一、非空的精确原文; needs-decision/no-change 时为 null. 固定范围模式不接受该字段. 输出仅此模式扩展, 没有新 Codex RPC 字段或技能路径. 生成提案及采用前均以实际解析范围检查只读标记, 候选窗口中的只读邻段不自动禁止其他个人内容的修改, 也不能成为可采用目标.

写回重用 ConfirmedWriter/ObsidianWriteHost: 预览 → 明确确认 → 校验目标/哈希/唯一块 → 检查当前编辑器和文件 → 先保存 pending 日志 → Editor.transaction 或 Vault.process 比较写入 → 回读 → applied. 替换范围外必须逐字保留. 编辑器支持未保存文本及原生撤销, 多编辑器不一致/多入口时拒绝. 重复点击、重启后的 pending 恢复、陈旧预览、迟到输出均有拒绝或去重路径. 提案不提供新建/删除文件、批量操作、路径迁移或任意执行; 讲义新稿继续走原工作台.

独立设备本地存储 `codex-sidebar-edits:v2:<vault-name>` 使用 schemaVersion=2, 不混进远程聊天或学习记录. 初次从旧 v1 复制并验证固定范围记录, 保留旧键原字节作为 0.9.0 回退副本; 后续 v2 写入不覆盖它. 最多 50 个任务/提案、约 200 万字符 JSON; 达上限明确报错, 不自动丢弃旧记录. 插件设置可导出完整 JSON 和二次确认清除; 导出含原文基线. 清除同时清空 v1 回退副本, 保留必要的 pending 写回日志, 不改笔记, 旧提案不能再采用或撤销. 正在写入/撤销时禁止清除, 清除期间迟到模型结果不得恢复任务. 未知 schema/损坏数据原样保留, 不静默覆盖. 当前没有导入记录功能.

“编辑并重发”和“重新发送”复制原任务/来源/私有本设备基线到新分支. 原任务保留, 不换成当前焦点或重新捕获. 别的设备只有远程聊天、缺少原私有基线时明确拒绝重发写回和采用; 明确重新捕获后才能新建修改任务.

## 迁移与回退

Windows 日常安装经用户明确授权从 0.6.2 更新到 0.9.0, 旧四个构建文件和 data.json 留有仓库外备份, 原聊天、具体模型/档次/Fast 选择、当前会话和连接模式保留. 安装其他设备前也应保留构建文件和数据, 不覆盖配对配置或学习记录. 旧版完全匹配的默认提示词升级为客户端确认写回说明, 自定义文本保留; 每轮仍附固定数学规则与修改能力边界.

仅升级插件四文件即可使用普通 Markdown 改稿, 兼容现有 0.8.0 桥. 重新打开侧栏, 明确重新捕获旧选区 (旧版消息可能没有版本). 不将旧文本建议自动升级为可写入提案.

回退只恢复插件构建文件, 保留 data.json 和设备存储. 回退不会自动恢复已采用的笔记; 请先安全撤销或使用 Obsidian 文件历史/自己的备份. 旧版不能呈现新提案确认控件, 不因此清除本地记录. 本版 iPad 真机改稿尚未验收.

0.10.0 回退到 0.9.0 时, 旧版继续读取 v1 副本, 看不到 v2 的新自选提案/采用记录, 不把它们强制降级成旧固定范围. 回退前导出 v2 并处理需要的安全撤销. 折叠偏好是独立本地键, 回退不会改模型选择或学习数据.
