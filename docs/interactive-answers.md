# 让解释带上图、关系和推导步骤

从 beta.20 起, 选中一段完整回答, 旁边会出现 **展开这一步 / 举个例子 / 说通俗些**. 点击后问题与原回答引用先放进草稿, 再点“提问”发送; 已有草稿不会被替换. 默认先解释疑点, 再给整合后的完整说明. 收起、Esc 或滚动可关闭临时操作条, 不长期占用阅读区.

模型也可按需附关系图与推导步骤. 点关系节点查看对象、条件及核对后的来源; 用“上一步 / 下一步”对照推导. 完整证明仍先在正文给出, 不需要逐步点击才能阅读. 节点/步骤中的解释动作同样只带入草稿, 不自动发送或写笔记. [原创对偶映射示例](../examples/interactive/duality.md)展示方向与线性推导.

从 beta.18 起, 捕获一段笔记或 PDF 后像平常一样提问, 例如:

> 这里的参数从 1 变到 4 时, 函数怎样变化? 我很难把式子与变化对应起来.

模型会自行判断是否需要参数图或符号/条件卡, 不需要每次写“画图/卡片”的固定口令. 也可以明确要求某种组件, 或说“只用文字”“只回答一句”. beta.17 用户可继续明确请求“附可调参数图及符号说明”.

回答仍先给出完整 Markdown 和公式. 模型提供有效的交互数据后, 下方会出现参数图和“符号与条件”; 普通问题不强制添加卡片. [原创热方程示例](../examples/interactive/heat.md)和[矩阵交换子示例](../examples/interactive/lie.md)可用作捕获来源, 文件中的代码块也展示了交互数据格式. 旧回答仍按原样阅读, 不会后台补生成交互数据.

## 模型何时主动使用

- **参数图:** 变化或情形差别是理解重点, 有现有一元函数图能表达的可靠函数/示例, 调整参数能观察到有关现象. 整数/正参数条件保留, 有限窗口不冒充原定义域.
- **符号与条件:** 多个空间/映射/对偶对象易混淆, 关键假设需要与步骤对照, 或长文需要反复回看定义/出处. 单个普通变量或一句话就能说清的内容通常直接解释.
- **关系图:** 对象、映射方向或依赖关系是主要理解障碍, 节点和箭头确有对照价值. 不用箭头暗示尚未证明的蕴含.
- **推导步骤:** 多个连续步骤需要逐项对照依据与条件. 完整推导先写在正文, 控件只是帮助定位; 单步纠错不强行拆成流程.
- **不附组件:** 没有具体观察/定位收益, 用户限制为纯文字/短答, 或当前是修改提案 JSON、补全、翻译、纯排版任务. 不为抽象对象硬凑曲线, 不生成空卡片.

模型在同一轮内部作出判断, 不增加一次分类请求. 追问仍遵循原来的完整整合/局部范围规则, 但不机械复制上一轮全部控件; 未通过追问发出的本地参数调整不会被当成模型已知状态. 原材料存在对应定义/条件原句时应逐字引用以便定位; 确实没有出处时可提供标明为 AI 说明的符号卡, 不编造引用. beta.20 保留 beta.19 的自定义 API 提示词去重, 同时迁移已知旧默认规则.

## 调整参数, 再带入追问

- 拖动滑块, 曲线和数值在本地更新. “重置参数”恢复模型给定的初值. 没有网络调用或自动写笔记.
- 纵轴固定, 便于比较振幅; 超范围部分裁切. 非有限值、未定义采样点会断开并显示提示. 曲线是有限采样图.
- 点“带当前参数追问”把参数和原回答引用放入提问框, 核对或补写问题后再点“提问”. 不覆盖已有草稿.
- 参数按设备、连接作用域、会话、消息及交互数据版本保存. 切换会话或重开后恢复; 不与另一设备的参数自动合并. 保存失败时仍可操作, 状态栏说明未保存或冲突.

首版支持一元 $y=f(x)$ 图、最多四个参数, 每份回答最多两幅图. 不支持模型生成的任意程序、三维应用或远程编译.

## 查看符号、使用条件和出处

点“符号与条件”中的符号查看说明. 原生 MathJax 提供准确 TeX 且与卡片唯一匹配时, 正文中的行内公式也会有点状下划线, 可点击或用键盘打开说明; 可以“返回刚才的符号”. 没有准确 TeX 元数据的渲染器仍可使用符号按钮, 不按字形猜测匹配.

来源引用须逐字匹配本轮原始快照或实际补读片段. 匹配后可“定位原文”或“打开原 PDF 来源”, 并显示映射、捕获时间、截断情况和 Windows 副本身份. 原文件变化时沿用既有版本/锚点检查, 提示变化或只打开准确文件. 重复引用、找不到原文和无文字层图像不会得到虚构定位. 引用匹配表示出处文字存在, 含义和条件仍是 AI 给出的说明.

“追问此符号”同样先填入提问框, 保留产生该回答时的原来源. 修改笔记继续使用原有“生成修改预览 → 用户确认”流程.

## 复制普通阅读版

“复制阅读版与当前参数”复制完整 Markdown、当前参数、符号说明及引用核对状态, 不带运行时控件. 复制的引用片段作为普通 text 代码块保留, 不执行其中代码. 原有复制、会话导出仍保留原回答文本和交互数据, 不暗中改变历史.

## 协议与接入

采用固定的 `codex-ui` JSON 协议, 不增加 OpenUI/React 依赖或模型脚本执行. beta.20 在原 schemaVersion 1 上添加可选 `relations` 和 `walkthroughs`, 旧 `plots/symbols` 回答和设备参数继续使用原规则. [ICAP 设计取舍](research/icap-intelligent-ui.md)是本轮依据.

模型在完整正文后附一个顶层代码块:

````markdown
```codex-ui
{"schemaVersion":1,"plots":[{"id":"heat","title":"衰减曲线","expression":"exp(-t)*sin(x)","x":{"min":0,"max":3.141592653589793},"y":{"min":0,"max":1},"parameters":[{"name":"t","label":"时间 t","min":0,"max":5,"step":0.1,"value":0}]}],"symbols":[{"id":"time","symbol":"$t$","meaning":"时间参数","conditions":"$t\\ge0$","quote":"设 $t\\ge0$."}]}
```
````

- 最多一个代码块, JSON 合计 24,000 字符, 最多两幅参数图、十二个符号、两组关系图、两组步骤. 未知字段、非法表达式、重复 ID、截断或未完整完成的回答不启用控件, 原始文本仍可阅读/复制.
- `relations` 每项为 `{id,title,nodes,edges}`. `nodes` 最多8项, 字段与符号卡相同; `edges` 最多12项, 每项 `{from,to,label}`, 端点必须引用本组真实节点. 布局、方向线和交互由宿主生成, 不接收模型坐标或事件代码.
- `walkthroughs` 每项为 `{id,title,steps}`. `steps` 最多10项, 字段与符号卡相同; `symbol` 是步骤短标题, `meaning` 是实际推导, `conditions` 是所用条件. 步骤顺序不代替数学正确性检查.
- 表达式仅支持 `x`、显式参数、`pi/e`、`+ - * / ^`、括号及 `sin/cos/tan/asin/acos/atan/exp/log/sqrt/abs`. 最多 512 字符、256 token、32 层, 默认 257 个采样点. 数值范围绝对值不超过一百万. 不执行 JS/HTML, 不接收路径、工具或文件操作.
- 符号字段是 `id/symbol/meaning/conditions?/quote?`; `quote` 最多 512 字符. 解释采用受限数学 Markdown. 模型不决定真实文件目标, 宿主只使用已经保存的来源.
- 本机 Codex、独立远程桥和 API 直连沿用同一保存/重放链路. 原生整段收到完整回答后也可使用, 不依赖 SSE 或某厂商的严格结构化输出字段. Codex 每轮仍显式加载 math-writing, `turn/start` 不增加 skill 或客户端路径.
- `src/interactive/` 分别负责协议、受限 AST、绘图、来源匹配、设备状态与展示. 原始数据保存在既有消息 Text 内, 不改变会话 schema/远程协议 2. 客户端 localStorage 的 `codex-sidebar-interactive:v1:` 记录保存参数/所选符号、所选节点/步骤和组件版本, 不跨设备合并. 普通阅读版包含全部节点、关系、步骤和引用状态, 不仅是当前显示项.
