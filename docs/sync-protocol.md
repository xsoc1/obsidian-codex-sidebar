# 远程同步协议 2

本文件描述候选 2.0 的客户端自有 HTTP 同步层, 不改变官方 Codex app-server RPC. 产品版本从 `manifest.json` 的同一构建来源导出; `protocolVersion: 2` 与结构化能力独立协商. 实际交付与验收状态以 [本轮工作记录](reliability-suite.md) 为准.

## 作用域与数据身份

- 每个配对身份继续对应一个独立的后台 agent. 同一个配对密钥的多个客户端共享该 agent 与历史; 不同配对身份的状态、内容 blob、PDF 缓存与操作凭证隔离.
- `dataIdentity` 持久保存于该配对身份的同步日志, 与进程重启后变化的 `server` 分开. `agentInstance` 进一步区分同一桥进程中 CLI 子进程的替换. 稳定 scope 为 `dataIdentity:client`.
- 桌面本机状态与远程状态分开. 本机待发送意图 `Outbox`、连接密钥、设备修改/还原记录不进入远程 root 实体.
- 发现稳定身份变化时保留本机数据并停止自动恢复. 不把新身份的状态覆盖进原身份.

## 消息与操作

消息保留原 ID、Prompt、Task、选区、原文/引用快照和来源. 用户消息的这些输入不能在原消息 ID 下改写; 修改已发送输入仍走新分支/新操作. `InputLedger`、已确认的 TurnId 和实际补读索引属于可补充元数据. 同源服务器消息版本按持久单调 revision 比较, 不按字符长度或设备时间判断.

同一消息不能确定版本时, 主显示保留本机内容, 另存双方完整冲突证据. 操作也保留不可比较的输入、回合身份或终态证据; 有冲突的操作不能直接继续推理. 冲突导出含原文, 应自行保管.

| 状态 | 含义 |
| --- | --- |
| `local` | 原问题及不可变输入已在设备保存, 尚未提交 |
| `received` | 桥已持久保存该操作身份 |
| `submission-unknown` | 可能已提交推理, 需要查收据, 不自动再发 |
| `running` | 已关联当前后台运行回合 |
| `completed` / `cancelled` / `failed` | 已确认终态; 不同终态保留双方核对 |

发送顺序是: 保存消息与本地意图 → 取得稳定 scope 后以同一 operationId 绑定逻辑输入摘要 → 解析线程/技能/图像 → 上传内容分片 → 保存首次解析请求及摘要、`Attempted` 标记 → POST 推理. 宿主在替换技能路径和 PDF 引用后, 还会保存实际 app-server 请求的 `HostRequestDigest`.

同一 operationId 重复提交且逻辑输入/请求相同, 返回已有凭证; 输入不同则拒绝. 桥在持久保存 `submission-unknown` 后才调用 CLI. 若 CLI 调用后、保存结果前崩溃, 恢复的是未知状态, 不是再次提交. 桥或 CLI 重启后旧 `running` 也改为带更高服务端 revision 的未知状态, 保留原 TurnId、ThreadId 和结果凭证. 旧结果中存在 TurnId 不证明旧推理仍在运行.

删除会话产生永久保留的 tombstone. 旧快照、迟到回答、旧 `/state` 写入和待发送操作不能复活会话. 原操作的未知提交证据仍保留, 独立分支和修改记录不连带删除.

消息 tombstone 以 scope 内的 `DeletedMessages: [{SessionId, MessageId}]` 持久保存. 恢复时合并本机与远端标记并过滤双方旧消息; 同一消息 ID 位于其他分支会话时不连带删除. 对应操作标记 `MessageDeleted`, 未提交的待发送操作取消, 未知提交凭证保留. 服务端不再记录该消息的迟到检查点或把旧导入内容恢复成新版本.

## 能力与端点

`GET /info` 返回产品版本、协议、稳定身份、进程/agent 身份、能力和预算. 当前能力包括 `incrementalSync`, `operationStatus`, `snapshotPaging`, `readPaging`, `historyRead`, `historyReadBodyVersions`, `catalogInline`, `pdfImages`, `pdfRegions`. beta.2 新增的两项为可选能力, 协议仍为 2; 按具体能力选择路径, 不通过版本字符串猜测功能.

| 端点 | 用途 |
| --- | --- |
| `GET /sync/catalog` | root、设置、会话目录与删除标记, 固定 revision 分页 |
| `GET /sync/history?session=...` | 指定会话消息索引, 使用同一固定 revision |
| `GET/POST /sync/blob` | 当前配对作用域内的 SHA-256 内容分片 |
| `POST /sync/delta` | mutation ID、基准版本、各实体 Expected revision 与内容摘要 |
| `GET /operations?id=...` | 查询一个发送操作, 不触发推理 |
| `GET /operations?offset=...` | 操作凭证的一致快照分页; 输入/请求/结果/冲突由 blob 引用 |
| `POST /operations` | 持久化幂等的单次推理提交 |
| `GET /events?after=...&protocol=2` | 固定游标之后的事件及回答内容检查点 |
| `GET /sync/storage` | 当前配对的容量/检查点统计与受保护 GC dry-run, 不删除任何文件 |

目录快照固定实体行及首次游标, 之后发生的生成事件从该游标继续读取. 操作分页有单独不可变 snapshot 标识. 两种内存快照各保留最近 8 份, 过期时明确报错并从第一页有界重取, 不静默混页.

服务端为实体和发送操作维护持久单调版本. Delta 同时检查各目标的 Expected revision; 无关实体更新不阻止本实体提交. 同一 mutation ID 绑定完整请求摘要并保存结果. 重复或模糊定位、同一 ID 不同内容、未知操作均拒绝. 冲突返回当前实体的版本和内容引用, 客户端保存本机/远端完整证据.

设置拥有独立实体版本. 客户端保留本设备偏好, 记录本地设置基线摘要及相应服务器 revision; 未改动的本地偏好不会在读取历史时上传覆盖共享设置. 明确改值才按原 revision 做 CAS. 离线改值遇到远端更新时保留双方并报冲突. 被拒绝的值不会后台反复覆盖; 用户再次明确改值后才使用已核对的新 revision 提交. 冲突证据保留, 不因下一次保存丢失.

回答以完整、带版本的检查点传输, 客户端替换原消息, 不重复追加片段. beta.2 使用新增 UTF-8 字节达到 32 KiB 或等待 1000 ms 的双触发策略, item/turn 完成立即保存; beta.1 原为每 16 个事件保存. 作用域、会话、回合、消息共同构成检查点身份. 只有可替代正文合并, 输入/Attempted/接收凭证/回合绑定/终态保持事务屏障. 写入成功后才公布版本和终态事件; 磁盘失败保留待保存正文并报错, 重试只写存储, 不重发推理. 原始 delta 不混发给协议 2 客户端.

在事件循环正常调度、存储成功时, 未落盘尾部最多约 1 秒或少于 32 KiB 新正文; 单个大 delta 会立即触发. OS 挂起、慢队列和写盘失败会扩大窗口, 不是硬实时或断电零丢失承诺. 本机慢写时, 只在最后一个关键事务屏障之后按相同 key 替换待保存快照, 并保持最新快照写入顺序. 不丢弃关键事务来满足队列上限.

同配对其他客户端成功提交 delta 后会收到 `bridge/sync-changed`. 客户端跳过自己已提交的 mutation ID, 对其他客户端的变更进行只读快照恢复. 工具实际读取通过 `bridge/source-read` 传回版本化来源索引; 搜索命中不算阅读全文.

## 真实字节预算与保留规则

- HTTP 请求仍为 4 MiB, 客户端按 UTF-8 字节预检. 整体历史可以超过该边界, 无需把所有历史放入一个请求.
- 内容原始分片为 64 KiB, base64 封装后的分页预算为 128 KiB. 单个 blob 最大 64 MiB, 超限明确拒绝并保留原记录.
- 一次 delta 最多 64 个实体, 一次历史/操作页最多 64 个索引, 同时受 128 KiB 分页预算限制.
- blob 的键是规范 JSON 的 UTF-8 SHA-256. 相同内容在同一配对作用域去重, 读取时重新核验摘要. 传输去重不修改原快照或模型历史语义.
- 首版保守保留已提交 blob、幂等凭证和删除标记. 普通修改缓存到期不清理这些数据. 不实施没有安全证明的回收; 也不因容量紧张静默删除聊天. 这意味着长期磁盘占用仍需监控, 本版未承诺无限容量或自动 GC.
- 未完成上传分片不能当作已完成内容. 只在全部分片组装、校验并提交后清理该上传的已知分片.

## 恢复与迁移

客户端首先取得固定目录/删除标记、当前会话完整正文和全部操作索引. 运行/未知操作展开完整输入与请求证据; 已结束操作可保存 `Evidence.State=metadata` 与原内容 blob 地址, 真正核对/完整导出时再展开. 同一配对下 `Sync.History` 显式保存 unloaded/loaded/deleted 与 revision, 未加载不是空数组删除依据. 其他会话在打开、历史定位、分支重发等需要时补读, 全量导出先 `hydrate_all`, 不完整则失败. 读取结束重新检查连接、作用域和最后一次选择, 不让迟到数据切回旧会话.

加载粒度为会话: 当前会话仍读取完整正文, UI 的 40 条首屏/120 条最大挂载量不等于网络只下载 40 条. 其他旧会话的全文不再阻塞当前会话. 独立 blob 读取并发最多 3; SHA 校验的可重读缓存默认 8 MiB UTF-8 容量 LRU, 上传确认 ID 也有数量上限. JS 对象堆开销和权威当前状态不包含在该 8 MiB 指标内. 单 blob 大于缓存预算仍可读取但不常驻缓存.

`catalogInline:1` 时目录行可附 `Inline`, 最多 4 KiB 且仍按整页 128 KiB 限制, 客户端重新核对 SHA-256. 没有 Inline 的旧桥/较大元数据使用原 blob 路径. 因此旧桥目录请求数仍可能随会话数量增长.

冲突证据与待处理项、决议分开. `Sync.Resolutions` 保存 `SchemaVersion/Id/Scope/ConflictId/Conflict/Choice`, 身份由双方完整内容和版本产生, 采用哪一方需确认时重查. 本机事务成功后才移除 pending; 同一决议会在恢复/同步中集合合并, 相反选择都保留, 真正新版本仍产生新冲突. “采用本机”只确定客户端保留稿, 不覆盖已提交输入或远端正在生成的稿件. 冲突证据包含双方原文, 可随完整会话导出.

只读查询有界重试, 事件监听在短暂失败、前台恢复、进程变化或事件窗口过期后, 核对身份/能力、恢复固定快照和游标、核对操作, 再继续监听. 重复 start/resume 不建立多个轮询器; close 释放计时器. 未知推理、笔记写回和有副作用 RPC 不自动重发.

本机新状态使用独立规范文件. 首次迁移保存原字节备份, 转换、校验、stage 读回, 写 pending 日志后再切换规范文件, 最后标 committed. 正常保存使用固定 stage、事务日志和一份最近已提交备份, 写前重新比较当前文件. 中断后的 pending 部分写入只能由相同摘要的候选恢复. 已提交文件损坏/缺失时不会拿最初迁移稿覆盖后续消息; 保留备份和冲突供恢复.

桥保留旧 JSON 字节及 `.before-sync-v2` 备份, 新日志和不可变内容分开写入, 以 fsync、读回和同目录 rename 提交日志. 迁移可重入; 原数据、候选或合法并发内容不一致时停止并保留双方. 未来 schema 版本拒绝自动转换. 备份不是日后覆盖新状态的授权.

## 兼容矩阵

| 客户端 | 桥 | 支持范围 |
| --- | --- | --- |
| 旧客户端 | 旧桥 | 原有行为和原有请求边界 |
| 新客户端 | 旧桥 | 已验证的旧问答/状态功能; UTF-8 4 MiB 预检, 首次推理一次提交; 无操作状态能力时未知结果只能核对/明确新分支, 不盲重发; 无区域图/历史分页能力时明确提示升级 |
| 旧客户端 | 新桥, 该配对尚未启用协议 2 | 可用旧 `/state` 路径; 桥合并旧状态, 保留删除语义 |
| 旧客户端 | 新桥, 该配对已启用协议 2 | `/state` 只读仍可用, 整份 POST 明确拒绝并提示升级, 不能覆盖协议 2 新数据 |
| 新客户端 | 新桥 | 本文件定义的增量、固定快照、操作核对和区域图能力 |

旧客户端无法解析新 PDF 区域 schema 等数据时必须升级, 不把区域几何信息悄悄删除或改成另一张图. 协议 2 启用后不自动降回旧同步. 回退应先导出/保存新数据并按 [迁移与回退说明](migration.md) 操作, 不拿遗留整份状态替换较新的规范文件.

beta.2 客户端配 beta.1 桥可使用旧同步和无内联目录; 需要新版正文版本补读的长引用会明确提示升级. 旧桥工具说明沿用旧版本语义, 不发送它不支持的 source_version 字段. beta.1 不理解 beta.2 部分加载状态, 回退不保证可直接读其本地缓存; 先完整导出, 保留新数据副本.

## 数学历史读取与派生输入

`obsidian_history_read` 绑定宿主实际 scope/session, 客户端不能指定其他会话. list 使用独立目录快照, 最近 8 份、总 UTF-8 2 MiB、有效期 10 分钟; 重启或过期须重新列第一页, 不混用过期目录. read 的首段返回 `body:` SHA-256 版本, 包含 scope/session/message/field/该字段内容, 后续 UTF-16 字符偏移分页必须携带同版本. 目录 `directory:` 版本不能当作正文版本. 无关 reasoning/消息变化不影响原正文; 原文字段变化、删除或不同会话/字段必须拒绝. 额外 `source_version` 校验保存的引用原文身份, 不替代分页 body 版本.

原消息、Prompt、Quote、SourceBlocks 全部保留. 派生发送表示仅对同一消息/来源/版本的实际重复正文去重, 保留块 ID、范围和来源; 不能仅因文字一样合并不同角色或回合. 当前问题、工作说明、引用、恢复历史和图像参与统一保守字节规划. 必需原文只有在存在确切版本工具补读能力时才允许换为定位引用, 不用摘要冒充完整证明. 已知/未知模型窗口都受保守上限约束, 不等于模型实际最大 token 容量. 当前轮仍最多两张受支持 PDF 图片, 历史图片预算独立.

## 容量统计与 GC 边界

`/sync/storage` 区分当前正文、活动中间版本、操作证据和未完成上传, 报告检查点次数/失败等统计. 引用检查考虑当前实体、固定分页快照、操作输入/请求/结果/冲突、决议、事务候选/日志、备份、上传, 并要求外部有效事件/未决与迟到凭证的完整根集合. 目录变化、未知 schema、损坏或摘要异常会阻止回收判定.

生产调用尚不能证明所有外部根齐全, 因此 `CompleteRoots=false`, 不给出删除候选, `GarbageCollectionEnabled=false`. 临时测试中的完整根案例仅验证 dry-run 逻辑, 不能推出生产自动 GC 安全. 本版没有删除端点、后台清理或容量无限保证. 未加载/已删除会话并不意味着其 blob 无引用.

曾连接旧桥的本机操作仍保留原 `legacy:client` scope、摘要和输入证据. 升级连接的稳定 scope 不等于为这些旧操作补造新桥接收凭证. 它们不会以原 ID 在新 scope 自动重发, 未尝试的旧操作也不静默改摘要晋升; 无法核对时需用户明确新建分支. 桥导入旧 JSON 的 root 时排除 `Sync`/`Outbox`, 不把客户端旧操作误当成已接收的服务端操作.
