# 2.0.0-beta.25 — 长会话恢复不再被历史目录卡住

恢复会话时，插件会给模型附上一份简短的历史问题目录。旧版最多取 24 条，却没有按实际 UTF-8 字节预留目录空间，中文长标题或长路径可能让整轮在发送前被拦下，即使本轮选区很短。

新版仍用 8 KiB 恢复导航上限，超出时从目录中移除较旧的条目。必需的历史定位、用户约束、本轮原问题与选区不缩短，完整历史照常保存。支持历史补读的连接仍可按需查询目录并读原文。未尝试发送的问题可在原消息卡片上点「继续发送已保存问题」。

## 验证

- 以原创中文题目、长路径和 202 条消息复现旧版报错。修复后检查导航字节上限、最近目录条目、必需历史、用户约束和原始输入；必需约束单独超限时仍拒绝发送。
- 在 Windows Obsidian 中用同一条未发送的已保存问题、小段选区和原历史只读对照：旧规划器报错，新规划器的导航为 7,988 字节（上限 8,192 字节），保留 22 条可选目录记录。原消息、原输入和操作状态未改变，未调用模型。
- 本地 `npm run build` 和 `npm test` 通过：607 项通过，1 项可选基准跳过。
- 改动仅在客户端，不要求替换独立远程桥。本轮未做 iPad 真机发送。
