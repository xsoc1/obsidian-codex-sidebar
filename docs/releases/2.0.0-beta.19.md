# 2.0.0-beta.19 — 自动交互选择与自定义提示词兼容

正常提问即可由模型判断是否需要参数图或符号/条件卡, 不用每次输入固定口令. 先遵守任务和用户范围, 再找具体观察/定位收益、核对数学条件, 最后选择最少够用的组件. 短答、局部纠错、纯文字和结构化修改/补全契约优先; 追问不机械复制全部控件. 有对应原文定义/条件时逐字引用, 不编造出处.

本版保留 beta.18 的自动选择规则, 修正 API 快照模式下自定义提示词携带完整插件后缀时的重复注入. 先规范完整的已知托管后缀, 再把快照限制放在用户文本之后、统一规则之前. 自定义文字和未知片段不删改, 不通过移动快照限制来迁就去重.

[使用与判断规则](../interactive-answers.md). iPad/BRAT 选择 **2.0.0-beta.19**; beta.18 标签保持原样, 本轮最终交付使用 beta.19.

## 验证依据

- 自动选择已用7次隔离真实 Codex/math-writing 请求验证: 6类初始选择符合预期, 首次符号卡缺少可提供的原文引用; 补强引用规则后定向复验4张卡/4处逐字匹配. 参数图保留 k=1—4 的整数步长, 数值样例正确. 短答、禁用组件、局部追问和抽象对象没有多余图. 完整记录见[beta.18 的语义实验](2.0.0-beta.18.md). 本版默认提示词内容未变, 修复只影响携带完整宿主后缀的自定义 API 路径, 不重复未受影响的真实请求.
- 补充测试先复现两种重复: beta.17 完整后缀叠加新规则、当前完整后缀叠加自身. 修复后桌面/远程/API 均只注入一次规则; 自定义内容保留, 快照限制仍在其后. 编译后的移动入口以原生整段模拟 API 实际发出两个请求, 两种后缀均只有一套规则, 原输出/快照和密钥隔离继续沿用旧契约.
- Node24 构建通过, 最终全套580通过、0失败、1项可选性能测试跳过. 单元/HTTP替身不冒充厂商实际生成质量, Windows 本机与 iPad 真机分开记录. 本轮未改控件渲染, 沿用 beta.17 有效视觉/交互证据, 不重复截图矩阵.

## 升级与回退

仅升级客户端, 独立桥保持 beta.15. 会话 schema/远程协议2及 codex-ui v1 不变, 不增加分类请求、工具权限或新 skill 输入项. 程序与数据分别备份, 回退只替换程序; 如需恢复旧默认判断, 在旧版设置中明确重置工作提示词, 不用旧全量数据覆盖新聊天.
