# 2.0.0-beta.22 — Codex Ultrafast

在侧栏 **模型与选项 → 速度** 选择标准、Fast 或 Ultrafast。Codex 模型目录报了才提供相应档位。旧 Fast 设置保持 Fast，Ultrafast 需要手动选择；速度不改变思考档次。直连 API 和其他 Agent 不显示 Codex 速度。

Ultrafast 在 Codex 请求中使用 `serviceTier: "ultrafast"`，不是 Fast 的 `priority`。本机与远程问答、行内补全沿用同一选择；远程仍使用原协议 2。旧桥继续支持原档位，选用 Ultrafast 需 Windows beta.22 或兼容更新桥并重连。旧桥不会收到 Ultrafast 推理请求；升级桥程序无需重配设备或覆盖状态。参见[升级与回退](../migration.md#beta22-codex-速度)。

## 验证

- 本机 Codex CLI 生成的 app-server 类型包含 `model/list` 的 `serviceTiers` 和 `thread/start` / `turn/start` 的 `serviceTier`。实际目录中 `gpt-6.2-sol` 同时报告两种加速档；新建隔离、只读、无落盘线程回读 `ultrafast`，没有提交生成。
- 自动化覆盖旧 Fast、模型不支持、旧桥能力、编译后的移动端请求、新桥操作绑定与去重。浏览器夹具检查实际侧栏速度下拉、窄栏和旧桥提示。未测试推理耗时或 iPad 真机。
