# 明确选择提问或修改预览

日期: 2026-10-19. 版本: 0.13.0, 已经明确授权安装 Windows 日常库并发布 GitHub/BRAT 预发布版本.

## 使用

输入区保留两个固定操作: **提问**和**生成修改预览**, 以及原有停止按钮. 删除“本轮方式”和“原文类型”下拉框. Enter 固定提问, Shift+Enter 换行; Tab 沿用 Obsidian 原生行为, 中文输入法确认不提交请求.

要修改笔记, 捕获选区或当前位置, 输入要求后点“生成修改预览”. 例如“写一个简短的17题证明上去, 只需包含思路”. 在“修改范围”中仍可选择 AI 自选、严格选区/捕获块、当前整篇笔记. 完成后审核目标、实际原文和公式排版差异, 再确认写入. 按钮只选择任务, 不代替写入审核.

点击“提问”不会因为出现“修改”“写上去”等词变成改稿. 解释选区、检查证明等快捷操作保持问答. 引用助手回答时可继续提问, 预览按钮暂停; 取消引用并捕获笔记后即可生成修改预览. 忙碌或切换笔记期间两个提交操作均暂停. 请求未接受时保留输入, 迟到的接受结果不清除期间输入的新草稿.

原文类型由 AI 依据真实片段、来源快照和当前请求辨识, 混排内容按片段处理. 完整答案仍最小修补并保留原路线; 思路沿原路线展开; 讲义重排补写须有明确请求. 无法辨识授权或必须重建时交用户决定. 模型判断不构成正确性或权限认证. 宿主只读元数据、课程只读单元、PDF 限制、范围校验和确认写回均保留. 未标注的源书/教师题面仍需人工审核, 重要只读材料应设置宿主只读标记.

## 协议与迁移

删除了旧关键词分类模块, 提交只依据客户端明确的 question/edit 操作. 新改稿任务在现有 TaskSpec 中保存 `EditRoleMode: "auto"`, 使用 `Role: "note"` 作为通用宿主标签; 提示词明确该标签不等于内容分类. 此字段是客户端任务元数据, 序列化在现有 text 输入内, 不是新增 RPC 字段. 远程改稿仍仅传 text + math-writing skill, 每轮显式加载技能, CLI 继续 read-only/never.

修改日志继续使用 schemaVersion 2. 缺少新字段的历史任务保留旧显式角色与提示, 不重新推断. v1 修改记录按原规则迁移, 原键保留; 新字段出现在 v1 或未知取值时拒绝加载并保留原始数据. 问题重发/编辑重发/分支仍使用原任务和快照, 不换成当前笔记, 也不把旧普通问答升级为修改. 要采用旧普通回答, 请从当前输入框明确发起新的预览任务.

没有新增设置、后台任务、远程服务或跨设备记录合并. 不需要更改桥或配对密钥. 升级只替换四件插件资产, 保留 data.json 和设备本地存储. 如需回退, 恢复先前四件资产及保留的原数据备份; 不清空记录或让旧插件重写新记录. 新字段未改变目标/版本/操作语义, 但旧版重发不会具备新的自动辨识提示.
