# 流式回答的稳定渲染

0.13.3 是本地修复候选. 用户报告 Codex 回答时对话区抽动, 本轮先复现再修改渲染. 日常 Windows 插件仍为 0.13.2; 此候选没有安装或发布.

## 原因与修复

旧 render_messages 在每次流式刷新时卸载整份 Markdown 组件、清空消息区, 然后逐条等待历史消息渲染, 最后恢复滚动位置. 等待期间可见高度短暂下降, 浏览器将 scrollTop 限制到新的最大值, 随后又跳回底部. 相同历史也会重复解析, 历史文字选区丢失. 旧逻辑在开始渲染时记住的滚动位置还会覆盖等待期间用户主动向上阅读的动作.

实际 CodexView 浏览器复现使用原创文本和异步 SDK renderer 替身. 三条历史的可见内容高度由 2030px 降至 432px, 最小一条历史由 736px 降至 432px, 帧记录出现 scrollTop=0. 仅在离屏准备整份列表的单变量探针消除了高度塌缩, 仍会重建历史并重复调用 renderer. 因此修复同时处理提交时机和历史复用.

src/message-list.ts 按会话、消息 ID 和内容签名保留卡片. 仅对变化的卡片离屏准备, 全部准备成功且会话仍有效后同步更新 DOM. 每张卡片单独拥有 Obsidian Component, 被替换时才卸载. 新结果迟到、切会话、关闭和渲染失败时释放新资源, 不覆盖当下列表. main.ts 沿用原来的 MarkdownRenderer、工作台与修改预览, 未另写聊天系统.

滚动在提交时采用最新用户位置. 已在底部时跟随回答; 用户向上阅读后保留可见卡片的相对位置. ResizeObserver 监测公式、图片等延迟变化, 合并到所属窗口的一次 requestAnimationFrame. 消息区使用 overflow-anchor:none 和 scroll-behavior:auto, 避免浏览器自动锚定或主题平滑滚动与该逻辑竞争. 原有思考指示动画与 reduced-motion 规则保留, 不引入淡入或位移动画.

refresh 中相同来源快照的上下文预览不再反复重建, 保留展开和勾选节点; 勾选值仍随设置刷新. 关闭视图后清理缓存和计时器, 重新打开能重建预览. 快照原文、时间、映射、截断标记和 PDF 图片处理均沿用原实现.

## 复验

常规命令:

```sh
npm ci
npm run build
npm test
```

浏览器检查需要 CODEX_LAYOUT_BROWSER 指定 Chromium/Edge 可执行文件, CODEX_LAYOUT_APP_CSS 指向本机 Obsidian 公共 app.css. 这两个路径仅通过当前进程环境传入, 不写进源码或全局配置:

```sh
node scripts/check-stream-layout.mjs
node scripts/check-sidebar-layout.mjs
```

流式检查创建临时浏览器 profile, 打包实际 CodexView 并输出逐帧 report.json, 最后关闭浏览器. 不连接 Codex 或远程桥. 原生探针须在明确选定的原生库中以唯一临时插件运行, 核对测试前后状态并卸载; 不要用替换日常 main.js 的方式运行它.
