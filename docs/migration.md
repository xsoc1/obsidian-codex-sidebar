# 2.0 候选升级、迁移与回退

## beta.17 交互答案

本次只需升级客户端, beta.15 独立桥继续可用. 会话 schema/远程协议仍为 2, 原问答、来源和修改记录不迁移. 新组件数据保存在原回答的普通 Markdown 代码块内; 旧客户端显示完整正文及原始代码块. 设备参数独立保存在 localStorage, 不被远程聊天状态覆盖. 回退只替换程序, 旧程序忽略新参数记录; 不还原整份旧聊天状态. [使用说明](interactive-answers.md).

## beta.16

仅更新客户端即可，beta.15 独立桥无需升级。旧 API 连接和历史无需迁移；临时 Key 不会自动写入 Obsidian 密钥存储。在当前设备通过 [记住 API Key](backends.md#api-直连) 关联密钥后重开即可使用，关联不会改变历史身份。回退旧插件程序会忽略关联，旧版继续使用临时 Key；不要用旧数据覆盖新会话。

### BRAT 提示找不到 manifest.json

先在出错设备的 Safari 打开 [beta.16 清单直链](https://github.com/xsoc1/obsidian-codex-sidebar/releases/download/2.0.0-beta.16/manifest.json)。2026-11-10 本机读回 beta.16 与正式版 1.1.0 的独立清单均为 HTTP 200，ID 和版本正确；用户也确认 iPad Safari 可读 beta.16 清单。BRAT 下载失败也可能显示“没有清单”，不代表发布包缺文件；见 [BRAT 2.2.0 下载代码](https://github.com/TfTHacker/obsidian42-brat/blob/2.2.0/src/features/githubUtils.ts)。

- 直链打不开：先在该设备换一个能访问 GitHub 发布资产的网络，再试 BRAT。下载会从 `github.com` 跳转到 `release-assets.githubusercontent.com`，只打开发布页面不能验证后一跳。
- 直链可读：在 BRAT 的插件列表编辑 `xsoc1/obsidian-codex-sidebar` 的跟踪版本，明确选 `2.0.0-beta.16` 后确认。已固定旧版本时不要用普通更新按钮等待自动升版。见 [BRAT 版本跟踪说明](https://github.com/TfTHacker/obsidian42-brat/blob/2.2.0/BRAT-DEVELOPER-GUIDE.md)。

无需卸载插件、删除目录或修改 API Key。若直链可读但指定版本仍失败，保留当前安装并提供 BRAT 版本和新的错误文字。

## beta.1 到 beta.2

规范文件仍为 schema 2, 同步协议仍为 2. 本次增加可选 `Sync.History` 加载标记、`Sync.Resolutions` 冲突决议和已结束操作的 `Evidence` 内容引用. 原记录不批量改写, 不补造未知 Phase/完成状态. 本机历史与远程配对身份不变, PDF 图片与修改数据库不迁入会话状态.

首次恢复只载当前会话正文及运行/未知操作证据. 其他会话显示目录并标记 unloaded, 打开、引用跳转、重发和完整导出按需读取. 本地较新消息和删除标记继续保留; 失败不会把未加载当成空历史写回. 快速切换时仅最后一次选择生效. “采用本机”保留当前显示及审计选择, 不授权改写已提交输入或远端正在生成的正文.

新增 `historyReadBodyVersions` 与 `catalogInline` 能力单独协商. 旧桥没有内联能力时使用 blob 读取; 没有正文版本补读能力时, 依赖它的长引用明确拒绝并提示升级, 不省略必需原文. 升级先桥后客户端.

回退到 beta.1 时, 旧程序不理解 unloaded 和轻量 Evidence, 不能直接将部分加载文件当作完整权威状态. 先在 beta.2 中完整导出, 保留当前规范文件、全部桥 blob/日志、浏览器草稿和修改数据库, 在独立副本核对兼容性. 本版没有自动降级工具. 换旧程序不等于批准用旧备份覆盖升级后新历史.

## 升级顺序

1. 先保存正在编辑的内容并结束已知运行回合. 未知提交保留原操作, 不能以重发来代替核对.
2. 备份当前插件目录和独立桥的 StateDir, 连同设备本地浏览器/IndexedDB 数据及状态旁的 `.receipt-*.json` 迟到证据文件。 这些是私有数据, 不上传到 GitHub. 新候选包没有配置、配对信息、会话或技能.
3. 经用户明确授权后, 先替换并启动新桥, 再升级配对客户端. 不把旧桥数据目录更换为空目录, 不更换配对身份. 升级检查不会代做此步骤.
4. 客户端设置中执行“环境检查”, 核对当前库、产品版本、协议能力、模型和 math-writing. 桥和插件需要完整 Codex CLI 运行包, 桥使用 Node 24.
5. 核对原问题、来源、分支和笔记映射; 用原创小样提问并重连. iPad 保持 Obsidian 在前台, 在实际使用网络和 VPN 下复验.

旧客户端向新桥初次启用协议 2 之前仍可使用旧接口; 某一配对启用协议 2 后, 该配对的旧整份状态写入明确拒绝. 因此同一配对的客户端应一起升级. 不同配对与 Windows 本机会话继续隔离.

## 客户端文件

新规范会话文件位于插件目录, Windows 本机为 `desktop-state-v2.json`, 远程为 `remote-<原 CacheId>-state-v2.json`. 桌面 `data.json` 与旧 `remote-<CacheId>-state.json` 原字节保留, 不再作为新版本的日常保存目标. 首次迁移增加 `SchemaVersion: 2`, 保留未知根字段、原消息/Prompt/快照/任务和身份; 不补造旧记录缺少的元数据.

迁移按备份 → 转换验证 → stage 读回 → pending 日志 → 写入规范文件 → 读回 → committed 进行. 原文件旁 `.pre-v2-<摘要>.json` 是字节备份; 规范文件旁 `.migration.json` 与 `.migration.tmp` 是迁移凭据. 中途退出时只恢复经校验的同一候选, 原数据并发变化则保留双方并停止. 未来 schema 不自动降级.

正常保存使用 `.save.stage.json`, `.save.journal.json`, `.last-committed.json`, 并核对当前文件未被另一个窗口修改. 卸载或更换连接后, 晚到的原操作凭证存为原规范路径下的 `.receipt-<操作摘要>.json`, 不拿旧内存整份覆盖新数据. 不同终态保留双方冲突证据. 已提交文件损坏或缺失时不会回放最初迁移初稿.

笔记关联、折叠状态、独立修改数据库、补全状态沿用原机制. 新提问草稿按设备/连接/会话隔离, 在本设备 localStorage 保存; 恢复旧来源需要可见确认, 不把它静默当成当前选区. 不默认跨设备合并浏览器草稿或修改数据库.

## 桥数据

每个配对从原 JSON 独立转换, 旧字节与 `.before-sync-v2` 备份保留. 新 `*-sync-v2.json` 保存稳定数据身份、单调版本、删除标记、操作与幂等凭据; `*-blobs` 保存摘要化的不可变内容, `*-upload-parts` 只用于未完成上传. 运行进程/CLI 子进程身份与数据身份不同, 重启不创建新的配对历史.

保存的操作 ID、逻辑输入和首次解析请求都有摘要. 桥在 CLI 调用前持久保存未知状态; 调用后崩溃、丢失回包、旧 Result 有 TurnId 都不能证明请求未发或仍运行. 自动恢复只做读取、核对与监听, 不自动重发推理或笔记写回.

新客户端曾连接旧桥时, 已保存操作可能仍绑定 `legacy:<client>` 身份. 升级桥不会改写这条旧操作的 scope、摘要或输入, 也不会伪造新桥接收凭证. 无法核对时明确保留未知, 用户可明确新建会话/分支, 不能把旧操作自动当作未提交重发.

会话删除标记和 `DeletedMessages: [{SessionId, MessageId}]` 消息标记均持久保留. 同一会话的旧快照、流片段与晚到检查点不会恢复已删除消息; 独立分支里同 ID 的副本不连带删除. 未知操作仍保留核对凭据. 本候选保留原有确认删除会话入口, 没有另加删除单条消息的界面.

此版不自动回收聊天 blob、未核对操作、幂等凭据和 tombstone. 磁盘容量不是无限, 超预算明确报错; 不通过删除历史解决. 修改/撤销缓存仍按原会话后续成功 N 轮计数, 默认 1, 可设永不; 不影响这些可靠性数据.

## 冲突与回退

侧栏可查看、导出本机与远端完整冲突证据. 只有定位明确的单条消息允许再次确认采用某一方; 设置、操作身份或多份冲突不猜选. 这不写入笔记、不重新提交推理. 文件事务冲突保留当前文件和候选, 不覆盖后续编辑.

**代码回退与数据回退不同.** 暂停候选后可换回旧插件/桥程序, 但旧版不读取新的规范会话、协议 2 或 PDF 区域 schema. 不可用旧整份备份覆盖升级后新增的消息. 应保留所有新文件与浏览器数据, 在独立副本上核对和导出, 或重新启用本候选读取. 本版不提供把协议 2 无损降成旧桥写模式的自动工具.

恢复桥时保持新版本的数据目录和配对身份, 不删除同步日志来逃避旧客户端拒绝. 已迁移数据是否可被某个旧版本消费, 以兼容矩阵和实际字段为准. 日常安装的回退应在部署前另存完整数据并核对; 本版部署的备份与回读结果见验证记录.

## 最短设备复验

- 原笔记 A 选段提问, 切到 B 后回 A, 原回答的相对链接、来源与阅读位置不漂移.
- 准备中停止, 草稿/引用仍在; 生成中停止等待后台确认. 锁屏或切网络返回后核对原操作, 不重复点重发.
- PDF 同页整图加局部图共两张, 核对页码、版本与公式; 重连重发沿用原图, 缺图明确拒绝.
- 用原创临时笔记生成修改预览, 确认前零写入; 确认、冲突拒绝与安全撤销仍按原流程.
- iPad 真机、物理中文 IME、实际锁屏/Wi-Fi 切换验收本轮未完成. 已有 1.1.0 设备经验不等于本候选通过.
