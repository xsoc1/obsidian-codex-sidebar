# 按需读取与修改缓存

## 阅读范围和边界

用户已授权 Agent 根据当前任务需要, 从捕获选段扩展到整个当前 vault 的相关笔记. 通过原有 `obsidian_cli_read` 搜索、列目录、查看链接和大纲、补读原文. 不默认上传整个 vault, 不跨 vault、不读取隐藏配置/认证文件, 不提供任意 shell、eval 或模型直接写文件的能力. 修改仍必须由当前客户端预览、确认、复核版本后写入. math-writing 每轮显式加载及远程 never 审批策略不变.

原白名单实际上已允许读取当前 vault 中的其他笔记; 本版明确授权 Agent 自行选择必要来源, 并修复错误与长文续读. 远程读取仍发生在 Windows 的同步副本上, 不能冒称读取了 iPad 的未同步内容.

`read` 的分页属于插件工具参数, 不属于 Obsidian CLI 的官方参数:

```json
{"command":"read","params":{"path":"目录/笔记.md","offset":0,"length":24000}}
```

返回 JSON 包含 `source`, `text`, `offset`, `total_chars`, `next_offset`, `truncated`, `version`. 用返回的 `next_offset` 和 `version` 继续读取. 偏移按 UTF-16 字符计, 单页最多 64000, 默认 24000. 版本变化拒绝拼接, 需从头重新读取. CLI 单次输出有 8 MiB 上限, 超限明确失败, 不声称完整读过. 搜索等列表输出过长时仍标记截断, 应缩小范围/limit. 不把读到的内容或工具输出视为执行指令.

分页和错误修复同时用于桌面与新版 Windows 远程桥. 旧桥仍可按原协议读取相关笔记, 但不支持新增分页参数; iPad 要使用分页需更新并重启独立 Windows 桥. 客户端更新不能替换正在运行的旧桥.

## 运行包定位

本机诊断发现已选中的 Codex 应用缓存目录仅剩 `codex.exe`, 缺少 `codex-code-mode-host.exe` 等配套程序. 原 CLI 元数据读取正常, 但真实模型回合未向插件发出工具请求, 回复报告工具宿主缺失. 完整运行包对照及新定位逻辑下的两次真实回合均成功调用 `version`、`files(total)` 并取得工具返回. 这验证了本次实际读取链路恢复; 不将模型自述单独当作系统错误证据, 也不宣称排除了所有读取故障.

`src/launch.ts` 仅识别 Codex 应用的 `OpenAI/Codex/bin/<16位缓存ID>/codex.exe` 布局. 完整的已选运行包保持不变; 选中包缺文件时, 在同一 bin 目录的合法缓存子目录中选择最近的完整包. 要求 CLI、code-mode host、command runner 和 Windows sandbox setup 齐全. 未找到则给出明确的设置提示. 任意自定义/便携 CLI 路径不自动替换. 不下载、复制、混搭二进制, 不改已存路径、登录文件、全局配置、权限或其他 Codex 进程.

这一缓存布局处理是插件兼容逻辑, 不是官方对目录结构的稳定承诺. [官方 app-server 文档](https://learn.chatgpt.com/docs/app-server#connect-a-remote-code-mode-host)说明其默认启动本地 Code Mode host. 曾尝试只对子进程关闭 Code Mode, 实测仍失败, 已撤回该无效方案; 不以绕过宿主依赖或权限替代完整运行包.

## 修改和还原的保留时长

在插件设置中找到“修改与还原缓存保留轮数”, 输入 `1`–`1000` 或“永不”. 默认 `1`, `0`/`never` 也表示永不. 设置存入当前设备当前 vault 的独立修改数据库, 不进入整份远程聊天状态覆盖.

- 完整修改预览生成后开始计时, 生成它的那一轮不计入. 未采用的预览同样到期.
- 确认采用、或安全还原完成并回读后重新计时. 倒计时与完成写回日志在同一存储事务中提交.
- 只计原会话后续成功完成的对话; 中断、失败、推理片段、重复事件及其他会话/设备的对话不计入. 折叠、重开侧栏和重启不重置计数.
- 到第 N 轮完成时, 清除该项提案、原文基线和还原日志, 显示已到期状态, 不再显示采用/还原按钮. 不修改笔记、不删除聊天, 聊天中的原始任务/来源快照仍保留.
- 写入中的 pending、UndoPending 恢复日志及冲突记录不自动删除. 存储失败保留原记录并在设置中说明, 不持续重复重试.
- 老版本记录没有会话计数元数据, 不追溯清理. 更改设置只重置已跟踪且尚未清理的缓存. 从“永不”改回有限轮数时从当前已知历史重新计数.

范围按“连接/配对设备 + 会话 ID”隔离. 不依赖笔记路径推测归属, 不把后台复习或补全请求当作对话. 已删除会话不会再产生后续轮次, 其独立修改记录仍可按原有手动导出/清除方式管理.

## 存储和回退

扩展的设备数据仍为 schemaVersion 2, IndexedDB 打包索引仍为 schemaVersion 3. 可选 `CacheTurns`, `ExpiredIds` 与每条记录的 `Cache` 保存策略、到期标记、所属会话、已计数轮次和剩余轮数; 均运行时校验. 缺少这些字段的旧数据原样保留. 清理通过原事务队列提交, 未引用的文本 blob 由 IndexedDB 保存流程回收, 不清空其他设备或整个数据库.

升级前可导出完整记录. 代码回退保留设备文件与数据库; 已到期内容无法靠回退代码恢复. 不恢复旧整份聊天状态覆盖后续记录. 旧版不支持此自动保留策略, 不会因此执行自动清理; 本次没有安装/发布授权时, 日常安装和远程桥保持原版.
